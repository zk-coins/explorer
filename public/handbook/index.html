Explorer handbook

Stateless presentation of the public L1-anchor layer and bearer disclosure routes. Every screen below is driven by deterministic fixture data and locked by a chromium-linux Playwright visual baseline.

Suite e2e/01–10 Upstream mocked node origin only Baselines chromium · linux

06 Addr link

e2e/06-addr-link.spec.ts · route /addr/

§5.8 address view: empty fragment, incoming-only (32 B ivk) and full (64 B ivk‖ovk) modes. Without holder/relay hints the explorer shows honest history-not-resolvable — never a fabricated empty payments list.

06-addr-empty
fragment-empty grammar for addr links.
06-addr-incoming-only
ivk-only mode + history-not-resolvable.
06-addr-full-mode
full (ivk ‖ ovk) mode label.

07 Authorised vs unauthorised

e2e/07-bearer-authorised-vs-unauthorised.spec.ts · route /tx/#…

Flagship contrast on the confirmation link: real ZBE open under the correct zkview versus the same ciphertext opened with a wrong bearer secret (AEAD auth failure).

07-tx-authorised
confirmation-view with blob_id / zbe_open / coinproof_decode all pass.
07-tx-unauthorised
error-state + check-zbe_open fail (wrong zkview).
